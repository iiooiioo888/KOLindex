# ADR-007 風險修補順序

- 狀態：已接受為本階段決定
- 日期：2026-11-25

## 決定

承認當前是原型。修補順序固定為：

1. 堵住認證缺口（網頁 `KOL_PROD` 強制 `KOL_GATE`；`kolindex-api` 用 `packages/api-auth` 或 `apps/api-gate`）
2. 打可引用的 `v0.1.0` Release
3. 人物主檔脫離「只有抖音作者清單」（P0 產品假設）
4. 前端遷移仍遵守 ADR-005：沒有 SSR 需求前不整站搬進 Next.js

## 為什麼

安全缺口是唯一「今天不修、對外就可能出事」的項目。Release 缺失修復成本低，卻讓外部無法引用現況。架構分裂與功能空心化要分階段，不能一次清零。

## 代價

本倉庫沒有 `kolindex-api` 原始碼時，API 認證只能以閘道或可攜中間件交付，還要在那台跑 API 的機器上掛上。Next.js 整站遷入暫不開始，避免和 ADR-005 對衝。

## 何時重審

`kolindex-api` 進到可改的倉庫之後，重審是否把閘道邏輯移進 API 本體並拆掉雙重代理。人物主檔有真實 `subject` ↔ 帳號映射後，再排 P1 席位可信度與 P2 分析功能。

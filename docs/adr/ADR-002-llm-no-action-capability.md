# ADR-002 分析模型沒有行動能力

- 狀態：已接受為 M0 架構決定
- 日期：2026-11-19
- 規範：KOL-SPEC-001 v4.1 第 11、15.3 節

## 背景

外部貼文、留言、OCR 與工具輸出都可能含提示注入。若分析模型能呼叫工具、讀秘密、寫資料庫或改政策，注入內容就會變成操作指令。

## 決定

1. 分析模型沒有 Function Calling、網絡、Vault、資料庫寫入與檔案寫入。
2. 不可信內容只放在 `untrusted` 資料欄位，不拼進系統提示。
3. 輸出只接受固定 JSON：`kind`、`severity`、`summary`、`evidence_ids`、`confidence`。Schema 外欄位丟棄。
4. `evidence_ids` 必須屬於本次允許清單。`severity` 由確定性規則再檢查。
5. 模型不得輸出 URL、內部路徑、憑證或命令。介面只依 evidence ID 向受控 API 取可見連結。
6. 結果只建立事件候選，不觸發採集、刪除、部署、權限或隊列動作。
7. `restricted` 資料不得送往外部模型。
8. 圖像分析不做身份識別、年齡判定或敏感屬性推斷。
9. OCR 與一般圖像分析先用本機模型：PaddleOCR、內部固定版本的 YOLO、FFmpeg/ffprobe。沒有 GPU，使用有並發上限的 CPU 隊列。
10. 文字分析暫定 Azure OpenAI，只限公司批准的亞太區域。該區域沒有指定模型時，不得自動改用美國或歐洲，必須改本機模型或等待合規批准。
11. 外部模型只接收 public 或已去識別的 internal。Confidential 與 Restricted 不外傳。啟用前要完成跨境轉移評估、供應商保留設定、零資料保留核對與合約審查。

## 後果

- 政策決定必須由版本化 YAML 與 Python 純函數做成，不能交給模型。
- M5 的紅隊測試要以「模型即使輸出指令也不能產生副作用」為阻斷條件。
- 本機 OCR 與圖像分析可以先設計。外部文字 API 在亞太區域名稱、跨境評估、零保留核對與合約審查完成前不得接通。

## 仍待確認

YOLO 的確切內部版本與映像 Digest，以及公司批准的 Azure 亞太區域名稱。這兩項未定之前，不得把任何分析映像標成 approved，也不得接通外部模型。
